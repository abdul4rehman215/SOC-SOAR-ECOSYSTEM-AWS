============================================================
DETAILED ATTACK LIFECYCLE
============================================================

Step 1:
Attacker sends malicious payload:
    GET /?q=<script>alert(1)</script>

Step 2:
NGINX forwards request to ModSecurity engine.

Step 3:
OWASP CRS rule matches XSS pattern.

Step 4:
ModSecurity blocks request with HTTP 403.

Step 5:
ModSecurity writes detailed log entry:
    - Rule ID
    - Severity
    - Matched payload
    - Source IP
    - URI
    - Timestamp

Step 6:
Fail2Ban monitors modsec_audit.log.

Step 7:
Fail2Ban regex matches:
    "ModSecurity: Access denied with code 403"

Step 8:
After 5 failed attempts within 300 seconds:
    IP is banned for 3600 seconds.

Step 9:
Firewall rule inserted:
    DROP traffic from attacker IP

Step 10:
Fail2Ban logs:
    "Ban <IP>"

Step 11:
Wazuh Agent collects:
    - ModSecurity detection
    - Fail2Ban ban action

Step 12:
Wazuh Manager:
    - Decodes logs
    - Applies custom rule
    - Generates alert (rule.id 100200)

Step 13:
Alert visible in Wazuh Dashboard:
    - Attack detected
    - IP banned
    - Rule ID
    - Log file source

Step 14:
Alert optionally forwarded to TheHive:
    - Case created
    - Analyst investigation
