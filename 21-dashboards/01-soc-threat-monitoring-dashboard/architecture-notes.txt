SOC Threat Monitoring Dashboard
Architecture and Data Flow

============================================================
1. PROJECT PURPOSE
============================================================

This project focuses on the dashboard engineering layer of the SOC.

Its purpose is to transform Wazuh security alerts into a practical
threat-monitoring dashboard that helps SOC analysts:

- identify high-severity alerts quickly
- detect common attack patterns
- spot top attacker IPs
- view geographic attack origin
- monitor attack spikes over time

The project does not focus on Wazuh deployment or agent installation.
Those setup components are documented separately in other repository
folders. This project assumes Wazuh alert data is already available.

  - creates visualizations for SOC operations

============================================================
4. DATA SOURCE USED
============================================================

Primary data source:
  wazuh-alerts-*

Important fields used in this project include:
  - timestamp
  - rule.level
  - rule.description
  - data.srcip
  - agent.name
  - agent.ip
  - rule.id
  - rule.firedtimes
  - MITRE-related alert context when present

These fields support severity analysis, alert categorization,
source-IP visibility, and time-based monitoring.

============================================================
5. THREAT MONITORING DASHBOARD COMPONENTS
============================================================

The dashboard is built from five main visualizations:

1. SOC - Alerts by Severity
2. SOC - Top Alert Types
3. SOC - Top Attacker IPs
4. SOC - Attack Source Geo Map
5. SOC - High Severity Attack Timeline

Together, these panels provide a compact and operationally useful
threat-monitoring view.

============================================================
6. VISUALIZATION-BY-VISUALIZATION ROLE
============================================================

A. SOC - Alerts by Severity
----------------------------------------
Purpose:
  Show distribution of alerts by Wazuh rule severity.

Helps answer:
  - Are alerts mostly low, medium, or high severity?
  - Is the SOC seeing increased higher-risk activity?
  - What should be prioritized first?

Main field:
  rule.level

B. SOC - Top Alert Types
----------------------------------------
Purpose:
  Show the most common alert categories.

Helps answer:
  - What detections are firing most often?
  - Are brute-force or authentication alerts dominant?
  - Which detections might be noisy?

Main field:
  rule.description

C. SOC - Top Attacker IPs
----------------------------------------
Purpose:
  Highlight source IPs responsible for medium/high-severity alerts.

Helps answer:
  - Which external IPs are most active?
  - Are there likely brute-force or intrusion sources?
  - Which IPs may need investigation or blocking?

Main field:
  data.srcip

Filter focus:
  rule.level between 8 and 15

D. SOC - Attack Source Geo Map
----------------------------------------
Purpose:
  Show geographic origin of suspicious activity.

Helps answer:
  - Where are attacks coming from geographically?
  - Are there repeated foreign-origin sources?
  - Is there clustering by region?

Main field concept:
  source-IP geolocation / GeoIP-enriched mapping field

Filter focus:
  rule.level between 8 and 15

E. SOC - High Severity Attack Timeline
----------------------------------------
Purpose:
  Show how medium/high-severity alerts change over time.

Helps answer:
  - When did activity spike?
  - Is suspicious activity recurring?
  - Are there bursty brute-force or scanning periods?

Main fields:
  timestamp
  rule.level

============================================================
7. FILTERING LOGIC
============================================================

This dashboard emphasizes medium to high-severity security activity.

Primary severity filter used:
  rule.level between 8 and 15

Why this matters:
  - removes some lower-value informational noise
  - keeps dashboard more triage-focused
  - highlights more actionable alerts
  - supports faster analyst prioritization

Some panels may use full alert data,
while others intentionally focus on severity-filtered activity.

============================================================
12. GEOMAP NOTE
============================================================

The Attack Source Geo Map depends on geolocation-capable source-IP data.

Depending on the Wazuh/OpenSearch setup, this may require:
  - GeoIP enrichment in the data pipeline
  - a mappable geolocation field
  - working source IP field population

The exported dashboard JSON preserves the working visualization state
used in this environment.

while the JSON preserves the actual dashboard object.

============================================================

This project represents the threat-visibility layer of the Wazuh SOC.

It converts Wazuh alert data into a practical monitoring dashboard that
helps analysts understand:

- alert importance
- dominant attack categories
- suspicious sources
- geographic attack origin
- attack timing and spikes

The architecture is simple in concept:

security events

    ->
