# 📘 Interview Q&A — SOC Threat Monitoring Dashboard

## 1️⃣ What was the main goal of this dashboard project?

The main goal was to build a **Wazuh-based SOC Threat Monitoring Dashboard** that helps analysts quickly monitor security alerts, prioritize high-risk events, and investigate suspicious activity visually instead of relying only on raw logs.

---

## 2️⃣ Why is a threat monitoring dashboard useful in a SOC?

A threat monitoring dashboard is useful because it gives analysts **centralized visibility** into active security events, alert trends, attacker sources, and severity levels, which helps improve triage speed and investigation efficiency.

---

## 3️⃣ What security problem does this dashboard solve?

This dashboard helps solve the problem of **manual alert review overload**. Instead of searching raw events one by one, analysts can quickly identify important patterns such as attack spikes, top alert categories, and suspicious source IPs.

---

## 4️⃣ Which data source was used to create the dashboard visualizations?

The visualizations were created using the Wazuh alert index:

```text
wazuh-alerts-*
````

This index contains the security alerts generated by Wazuh and indexed into the dashboard layer.

---

## 5️⃣ Why was `rule.level` important in this project?

`rule.level` was important because it helped measure **alert severity**. It was used to separate lower-value events from medium-to-high severity alerts and helped make the dashboard more focused for SOC triage.

---

## 6️⃣ Why did you focus on rule levels 8 to 15?

Levels **8 to 15** were used because they represent more meaningful security events for monitoring and investigation. This helped reduce noise and keep the dashboard focused on alerts that are more relevant to analysts.

---

## 7️⃣ What does the “SOC – Alerts by Severity” visualization show?

It shows how alerts are distributed across different Wazuh severity levels. This helps analysts quickly see whether the environment is experiencing mostly lower-risk activity or a larger amount of higher-severity alerts.

---

## 8️⃣ What is the purpose of the “SOC – Top Alert Types” visualization?

This visualization shows the most frequent `rule.description` values, which helps identify the **most common security alert categories** being triggered in the environment.

---

## 9️⃣ Why is the “SOC – Top Attacker IPs” panel useful?

It helps analysts identify the source IP addresses generating the most suspicious or high-severity alerts. This is useful for detecting brute-force sources, repeated intrusion attempts, and suspicious network-origin activity.

---

## 🔟 What value does the geo map add to the dashboard?

The geo map adds **geographic context** by showing where suspicious source activity is coming from. This can help analysts identify repeated foreign-origin attacks, regional patterns, and threat-source concentration.

---

## 1️⃣1️⃣ Why is the timeline visualization important for SOC monitoring?

The timeline helps analysts understand **when attack activity spikes**. This is useful for identifying bursts of suspicious activity, repeated attacks, brute-force periods, and changes in alert volume over time.

---

## 1️⃣2️⃣ How does this dashboard improve triage compared to using raw logs only?

It improves triage by turning large amounts of alert data into **quick visual summaries**. Analysts can first identify what matters through the dashboard and then drill down into raw events only where deeper investigation is needed.

---

## 1️⃣3️⃣ What kind of attack scenario can this dashboard help highlight?

This dashboard can help highlight attack scenarios such as:

* SSH brute-force attempts
* authentication failures
* repeated suspicious login activity
* scanning-related spikes
* concentration of alerts from the same source IP

---

## 1️⃣4️⃣ Why was the dashboard export JSON kept in the project folder?

The exported JSON was kept so the dashboard can be **re-imported and reused** later without rebuilding it from scratch. It also preserves the exact dashboard structure used in the project.

---

## 1️⃣5️⃣ What did this project demonstrate overall?

This project demonstrated practical skills in:

* Wazuh dashboard engineering
* security visualization design
* analyst-focused monitoring workflow thinking
* severity-based triage improvement
* source IP and timeline-based threat visibility
* documenting a reusable SOC monitoring dashboard project
