# 🎤 Sysmon for Linux + Wazuh  
## Interview Questions & Answers  
### Detection Engineering & SOC Focus

---

## 1️⃣ What problem does Sysmon for Linux solve?

**Answer:**

Linux systems often lack deep behavioral telemetry compared to Windows environments.  
Traditional logging mainly captures authentication logs and system messages, but not detailed process-level activity.

Sysmon for Linux provides:

- Process creation visibility  
- Network connection telemetry  
- File creation and deletion monitoring  
- Kernel-level event capture using eBPF  

This enables behavior-based detection rather than relying solely on static logs.

---

## 2️⃣ How does Sysmon for Linux collect telemetry?

**Answer:**

Sysmon for Linux uses **eBPF (Extended Berkeley Packet Filter)** to collect kernel-level events.

It monitors:

- Process execution  
- Network activity  
- File system operations  
- Process termination  

These events are written into system logs and forwarded to the SIEM.

---

## 3️⃣ How did you integrate Sysmon with Wazuh?

**Answer:**

Integration involved:

1. Installing Sysmon on the Linux endpoint.  
2. Configuring a Sysmon XML file to enable specific event types.  
3. Ensuring logs were written to journald/syslog.  
4. Configuring the Wazuh agent to monitor syslog.  
5. Creating a custom decoder on the Wazuh Manager.  
6. Developing base and detection rules.  
7. Validating event ingestion in the Wazuh Dashboard.  

This created a full endpoint → SIEM pipeline.

---

## 4️⃣ Why did you create custom decoders?

**Answer:**

Raw Sysmon logs are structured XML.  
Wazuh requires structured parsing to extract fields like:

- `system.eventID`
- `eventdata.image`
- `eventdata.commandLine`
- `eventdata.targetFilename`

Custom decoders allow field-based detection logic.  
Without proper decoding, detection precision would be limited.

## 5️⃣ What is alert noise and how did you reduce it?

**Answer:**

Alert noise refers to excessive alerts generated by benign system activity.

Examples of noisy processes:

- `nano`
- `bash`
- `cron`
- `systemd`
- `apt`

To reduce noise:

- Lowered baseline rule severity to level 0  
- Added suppression rules for known-good processes  
- Preserved telemetry while reducing alerts  

Result:

- ~80–90% alert reduction  
- Cleaner SOC signal

These generate **Level 10 high-confidence alerts**.
