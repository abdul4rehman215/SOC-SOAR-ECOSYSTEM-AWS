--------------------------------------------------
2. DATA FLOW EXPLANATION
--------------------------------------------------

1. Apache generates HTTP access logs.
2. Wazuh Agent collects logs.
3. Wazuh Manager parses logs and assigns rule.groups = web.
4. Events stored in wazuh-alerts-* index.
5. OpenSearch ML builds baseline of web rule frequency.
6. Anomaly Detector identifies deviation.
7. Alert Monitor evaluates grade + confidence.
8. Slack notification sent to SOC.
9. Analyst investigates in Discover.
10. Case created in TheHive.
11. Attacker IP blocked via firewall.

--------------------------------------------------
3. DETECTION ENGINEERING DESIGN
--------------------------------------------------

Detector Configuration:

Index: wazuh-alerts-*
Filter: rule.groups = web
Feature: http_error_count
Aggregation: value_count(rule.id)
Interval: 1 minute
Shingle size: 8

Reasoning:

- Aggregating rule.id captures web-related events.
- 1-minute interval allows near-real-time detection.
- Shingle size 8 improves anomaly sensitivity.
- Historical analysis establishes behavioral baseline.

--------------------------------------------------
4. ALERT LOGIC DESIGN
--------------------------------------------------

Trigger Conditions:

Anomaly Grade > 0.7
AND
Confidence > 0.7

Why both?

- Grade measures deviation severity.
- Confidence measures model certainty.
- Using both reduces false positives.
