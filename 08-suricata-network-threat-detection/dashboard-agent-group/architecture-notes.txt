3. AGENT GROUP ARCHITECTURE
------------------------------------------------------------

Agent Groups allow centralized configuration control.

Instead of manually editing each agent:

We apply configuration at group level.

Example:

Group Name: Suricata

Group Configuration File:
/var/ossec/etc/shared/Suricata/agent.conf

Any agent added to this group automatically:

- Ingests Suricata logs
- Applies consistent configuration
- Maintains centralized policy control

This allows horizontal scaling.


4. WHY AGENT GROUPS MATTER IN ENTERPRISE SOC
------------------------------------------------------------

In enterprise environments:

- Hundreds of endpoints
- Multiple IDS sensors
- Segmented networks
- Multiple detection policies

Agent groups provide:

✔ Centralized configuration
✔ Policy-based deployment
✔ Reduced configuration drift
✔ Clean separation of telemetry
✔ Faster rollout of updates

This aligns with enterprise security governance.


5. DASHBOARD ISOLATION ARCHITECTURE
------------------------------------------------------------

Without isolation:

- Network alerts mix with endpoint logs
- Authentication logs mix with IDS alerts
- Triage becomes inefficient

With dedicated Suricata dashboard:

- Only rule.groups: suricata visible
- MITRE tactics clearly grouped
- Top attacker IP ranking visible
- Alert trend spikes easily detectable

This supports focused network threat monitoring.


6. DASHBOARD DESIGN PRINCIPLES
------------------------------------------------------------

Panels Designed:

1. Top Suricata Signatures
2. MITRE Tactic Distribution
3. MITRE Technique Frequency
4. Alerts Over Time (Trend Analysis)
5. Top Source IPs
6. Alerts by Severity

Design Goals:

✔ Immediate threat visibility
✔ Attack lifecycle context
✔ Attacker prioritization
✔ Alert spike detection
✔ Severity awareness

8. SEPARATION OF TELEMETRY LAYERS
------------------------------------------------------------

SOC Telemetry Layers:

Layer 1 – Network IDS (Suricata)
Layer 2 – Endpoint Telemetry (Sysmon / Linux Sysmon)
Layer 3 – Authentication Logs
Layer 4 – Cloud Logs (CloudTrail)
Layer 5 – Application Logs

Part 3 enforces clean separation between:

Network detection vs Host detection

This improves SOC clarity and reporting.


9. SCALABILITY MODEL
------------------------------------------------------------

To scale this architecture:

- Deploy additional Suricata sensors
- Add sensors to Suricata agent group
- Maintain single shared configuration
- Keep centralized rule management
- Extend dashboard filters per subnet

This model supports:

✔ Multi-subnet environments
✔ DMZ monitoring
✔ Data center segmentation
✔ Cloud network IDS deployment
